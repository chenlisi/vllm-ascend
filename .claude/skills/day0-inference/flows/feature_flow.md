# Feature Flow（占位）— Day0 Stage 3：特性叠加版本（跑得快）

> ⚠️ **占位声明**：本 flow 尚未实现。主控 `SKILL.md` 推进到 Stage 3 时，应**显式提示【特性叠加 flow 尚未接入】**，输出本文件的框架定义供人工或后续版本接管，不得自行编造执行步骤。

## 阶段目标（对齐 AscendBot 四阶段定义）

基于并行量化版本，**系统性集成五项以上性能优化特性**（Prefix Caching、投机解码 MTP/DSpark、ACLGraph 全图、FlashComm、EP/EPLB 等，按模型适用性选定），构建高性能推理版本，并确保**多特性叠加后推理精度无劣化**。

## 入口条件（Stage 2 出口证据）

- 并行量化版本签收：并行策略报告 + 量化精度对比报告归档；
- Stage 2 配置下的精度基线（本阶段逐项叠加的回归基准）。

## 规划出口判据（草案，实现时细化）

1. **特性清单与顺序**：明确本模型叠加的特性子集（≥ 5 项或按模型适用性声明 not-applicable）与叠加顺序——**逐项开启、逐项回归**，禁止一次性全开；
2. **叠加精度无劣化**：每叠加一项特性，精度回归对齐上一配置（不是只对齐 golden 基线）；劣化项按 Delta Debugging 思路裁剪无关路径，定位到最小算子/特性子集；
3. **组合矩阵覆盖**：量化 × 图 × 投机 × CP/PD 的相关组合项全部有验证记录（对接 Designer 组合矩阵回归清单）；
4. **feature-first 证据**：失败项保留错误签名与复现命令，默认关闭必须附根因分析；
5. **图级别声明**：最终配置落在哪个图级别（eager / PIECEWISE / FULL_DECODE_ONLY / FULL_AND_PIECEWISE）有明确记录；
6. **图模式验收**：ACLGraph 逐级开图、六类不可入图排查与捕获计数的验收素材沉淀在 `.claude/agents/performance.md`，实现本 flow 时接入。

## 已知技术难点（实现时需覆盖）

- 特性组合易引发时序冲突与异常回退，根因定位链条长（如 MTP × prefix cache 静默输出损坏、DSpark × 混合 KV 分组 padding 膨胀等历史先例）；
- 精度劣化来源难定位——需要「采集 → 分析 → 诊断 → 验证」的闭环，而非盲试。
